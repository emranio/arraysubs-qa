Other text that points merchants to settings that do not exist:
- arraysubs/src/Features/RecurringBilling/Services/RenewalProcessor.php:852 private subscription note: "Automatic retries are disabled in the gateway settings. The next attempt requires a manual retry." Observed on subscription 68599 (customer 581, gateway stripe) at 2026-10-19 09:48:13 UTC. The admin detail page shows it as a System/Private note dated "19 October, 2026 3:48 PM" (site time, UTC+6) with no link (screenshot dv61-sub-68599-retry-disabled-note.png). For Stripe or Mollie this fires when the store-level payment_retry.enabled is false, which no admin screen can show or change. For PayPal or Paddle it fires because the gateway hardcodes enabled=false; no gateway setting exists there either.
- arraysubs/src/functions/gateway-helpers.php:237-239 docblock: "Gateways publish their own settings via the `arraysubs_payment_retry_config` filter (Stripe gateway exposes max_attempts and interval as admin-configurable)". There is no such admin configuration.
- documentations/user-guides/subscription-lifecycle-and-plan-switching.md:63: "Payment Retry Scheduled | ArraySubs scheduled another retry attempt according to gateway retry settings."
- Accurate counter-example: user-manual/markdowns/checkout-and-payments/automatic-payments/payment-recovery.md:45-58 ("Configuring the retry ladder") describes the store-level keys enabled, interval_hours and stop_on_hard_decline, names no settings screen, and says "These values live in the ArraySubs settings store and travel with **Import/Export Settings**." That matches the only UI path found (1-Minute Setup > Export/Import Settings, by hand-editing the JSON file).
